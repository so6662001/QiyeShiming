## 2. 关键技术组件

| 组件 | 选型方向 | 作用 |
|---|---|---|
| 实名认证 | 第三方电子签平台 / 云厂商实名 API | 身份二要素、运营商三要素、人脸核身 |

## 3. 实名与签署集成流程（时序）

### 3.1 经办人实名（一次性）
```
移动端 → 实名服务 → 第三方平台
  上传身份证OCR → 二要素/三要素核验 → (大额)人脸核身
  → 核验通过 → 平台签发个人数字证书 → 回写 operator.cert_id
  → 存证: 实名记录(method/result/时间) 哈希存证
```

### 3.2 提货指令签署（每次）
```
经办人发起指令 → 生成待签文件(指令内容+车牌+数量+时段)
  → 意愿认证(短信/人脸) → 调用电子签名(经办人证书)
  → 加盖可信时间戳 → 文件哈希上链/存证
  → 生成提货码 → 返回二维码+短码
```

### 3.3 出库回执存证（每次）
```
仓库核验提货码 → 过磅 → 出库放行
  → 生成出库回执(实提数量+出库时间+车牌+磅单)
  → 哈希 + 时间戳 + 存证(关联同一 pickup_order_id)
```

## 4. 存证证据链设计

### 4.1 一次提货的完整证据包
| 序号 | 证据项 | 来源 | 存证方式 |
|---|---|---|---|
| 1 | 实名认证记录 | 实名服务 | 哈希存证 |
| 2 | 提货指令（经办人签名+时间戳） | 电子签署 | 原文+哈希上链 |
| 3 | 提货码核验记录 | 仓库核验 | 日志哈希 |
| 4 | 车牌识别抓拍 | 摄像头 | 图片存OSS+哈希 |
| 5 | 过磅单（毛/皮/净重+时间） | 磅房 | 数据+照片哈希 |
| 6 | 出库单+出库时间戳 | 出库服务 | 原文+时间戳 |
| 7 | 闸口/磅房视频或照片 | 监控 | 媒体存OSS+哈希 |
| 8 | 结算单+送达记录+异议期 | 结算服务 | 原文+送达日志哈希 |

### 4.2 存证原则
- **原文 + 哈希分离存储**：原始文件存对象存储，哈希值上链/写入存证机构。
- **可验证**：任何时点可用原文重算哈希，与链上比对，证明未篡改。
- **可出证**：对接存证机构/公证处，按 pickup_order_id 一键生成存证报告或申请司法鉴定。
- **时间不可抵赖**：所有关键节点附可信时间戳。

### 4.3 证据链聚合视图
```
PickupOrder(id)
  ├─ RealnameRecord(operator)
  ├─ SignEvidence(提货指令签名+时间戳+chain_tx)
  ├─ PickupCodeVerifyLog
  ├─ PlateCapture(image)
  ├─ WeighRecord(+photo)
  ├─ Outbound(+time+gate_capture)
  └─ Settlement(+deliver_evidence+objection)
  → 一键导出: 存证报告.pdf
```

## 5. 接口清单（核心 API）

### 5.1 实名与证书
| 接口 | 方法 | 说明 |
|---|---|---|
| `/realname/idcard-ocr` | POST | 身份证 OCR |
| `/realname/verify` | POST | 二要素/三要素核验 |
| `/realname/face` | POST | 人脸核身 |
| `/cert/issue` | POST | 签发个人数字证书 |

### 5.2 提货指令与提货码
| 接口 | 方法 | 说明 |
|---|---|---|
| `/pickup/order` | POST | 发起提货指令（含意愿认证、签署） |
| `/pickup/code/{id}` | GET | 获取提货码/二维码 |
| `/pickup/code/refresh` | POST | 动态码刷新 |
| `/pickup/order/{id}/revoke` | POST | 撤销提货码 |

### 5.3 仓库核验与出库
| 接口 | 方法 | 说明 |
|---|---|---|
| `/warehouse/verify-code` | POST | 核验提货码+车牌 |
| `/warehouse/weigh` | POST | 录入/同步过磅数据 |
| `/warehouse/outbound` | POST | 出库放行+出库时间戳 |

### 5.4 结算与异议
| 接口 | 方法 | 说明 |
|---|---|---|
| `/settlement/create` | POST | 生成结算单 |
| `/settlement/deliver` | POST | 多渠道送达+记录证据 |
| `/settlement/{id}/objection` | POST | 买方提异议 |
| `/settlement/{id}/auto-confirm` | (job) | 异议期到期自动确认 |

### 5.5 存证与出证
| 接口 | 方法 | 说明 |
|---|---|---|
| `/evidence/save` | POST | 写入证据+哈希上链 |
| `/evidence/order/{id}` | GET | 聚合证据链 |
| `/evidence/report/{id}` | POST | 生成存证报告/出证申请 |

## 6. 安全与合规要求

- **传输加密**：全链路 HTTPS/TLS。
- **敏感数据加密**：身份证号、人脸数据加密存储；人脸特征建议不落地或脱敏。
- **最小权限**：仓管不可见完整身份证号等敏感信息。
- **审计日志**：关键操作全量留痕，不可删除。
- **数据处理协议**：与第三方实名/电子签/存证服务商签订 DPA。
- **降级与容灾**：仓库核验离线降级（纸质单 + 事后补录存证）；存证异步重试。
- **防套用**：提货码一次一码、绑车牌、限时、动态刷新（见产品设计第 3 节）。
