# 钢贸提货单实名签收系统 · 合规与法律效力设计

> 本文聚焦：如何让"提货确认/出库交付/结算确认"具备法律效力，以及个人信息合规要点。

---

## 1. 法律效力的总体逻辑

法院在纠纷中真正审查的是三件事，分别由不同机制解决：

| 法律问题 | 解决机制 | 说明 |
|---|---|---|
| 签字的是不是真实的人 | 个人实名认证 | 一次性，可复用 |
| 签署有没有法律效力 | 可靠电子签名（CA 证书 + 时间戳 + 防篡改存证） | 决定效力的核心 |
| 是不是本人真实意愿 | 签署意愿认证（短信/人脸/密码） | 每次操作 |
| 行为是否约束买方企业 | 合同预授权 + 职务/委托代理 + 提货码授权链 | 把个人/司机行为绑定到企业 |

> 关键结论：**企业实名认证不是法律效力的必要条件**，它主要用于风控。法律效力来自"个人可靠电子签名 + 授权关系证明"。

---

## 2. 可靠电子签名的法定要件

依据《中华人民共和国电子签名法》第十三条，"可靠的电子签名"与手写签名或盖章具有同等法律效力，须同时满足：

1. 电子签名制作数据用于电子签名时，**属于电子签名人专有**；
2. 签署时电子签名制作数据**仅由电子签名人控制**；
3. 签署后对电子签名的**任何改动能够被发现**；
4. 签署后对数据电文内容和形式的**任何改动能够被发现**。

### 落地要求

| 要件 | 实现方式 |
|---|---|
| 专有 + 控制 | 经办人个人实名 + 个人数字证书 + 签署时意愿认证（短信/人脸） |
| 防篡改（签名） | 由具备资质的 CA 机构（持工信部《电子认证服务许可证》）签发数字证书 |
| 防篡改（内容） | 文件哈希 + 可信时间戳 + 区块链/哈希存证 |
| 时间不可抵赖 | 可信时间戳（如联合信任时间戳服务中心 TSA） |

> ⚠️ **不要自建 CA**。无资质的电子签名在法律上效力存疑。应接入持牌 CA 或第三方电子签平台。

## 2.5 无独立购销合同时的条款载体与授权链

本业务从**留货单**开始，不签独立购销合同。法律上买卖合同无需以"合同"为名：留货单（载明品名/规格/数量/价格）+ 买方在线确认 + 实际提货，依《民法典》即构成买卖合同关系。原本应放在购销合同的框架条款，改由：

1. **《在线提货与签收服务协议》（开户一次性电子签署）**——承载预授权、自提交付与风险转移、驾驶员代提授权、结算异议期、电子签名效力、个人信息授权等全部框架条款；**建议由法人/负责人完成一次法人意愿认证（扫码刷脸）或加盖企业电子章**，以确立企业级意思表示（替代繁琐企业实名与授权委托书）；
2. **每张留货单的背书条款**——引用上述服务协议，经办人在线确认即生效。

> 授权链根基 = 服务协议预授权（企业级背书）+ 经办人个人实名电子签名 + 提货码 + 职务/表见代理。**授权委托书非必备**（详见第 4.3 节）。

## 2.6 企业级授权的建立与"企业不认可经办人"的应对

**风险**：开户若仅"业务员代录营业执照 + 采购员个人实名"，企业层面无任何意思表示，客户企业事后可抵赖"该采购员未经我司授权"，授权链在企业一环断裂。个人实名只证明"他是谁"，不证明"企业授权了他"。

### 2.6.1 必须的事前确权（开户硬门槛）

开户须完成一次**企业级确权**，按稳妥度择一，且**确权完成前采购员账号不可正式提货**：

| 优先级 | 方式 | 说明 |
|---|---|---|
| 首选 | **法人意愿认证** | 向法定代表人/负责人推送，扫码刷脸（比对工商登记法人身份）+ 电子签署《服务协议》（含授权经办人名单）。一次性、轻量，替代繁琐企业实名 |
| 备选 | **企业电子章** | 以企业电子印章签署《服务协议》 |
| 备选 | **线下盖章授权书** | 收取盖公章的《服务协议/授权书》并扫描固化存证 |
| 大企业适配 | **既有正式凭据 + 对公付款** | 接受盖章的《授权书/指定提货人名单》、采购框架协议/采购订单(PO)作确权；**对公付款本身即企业认可的强证据**。详见 2.6.5 |

> 该确权动作即《服务协议》第四条"企业授权与意思表示"，是替代企业实名/购销合同后**授权链的根基**。其具体强度可按客户信用分级（见 2.6.5）。

### 2.6.2 二级授权（企业管理员模式）

为减轻法人负担并解决经办人频繁变更，采用两级授权：

```
法人（开户一次确权）
  └─ 授权 1~N 名「企业管理员」(采购总监/负责人,需个人实名)
       └─ 管理员自助: 增/减/停用经办人、分配授权范围(限额/品类/仓库)
            └─ 经办人(实名)执行提货
```

- 每级均有**实名 + 电子签名 + 存证**；管理员经法人书面/电子授权，其增减经办人属职务/委托代理，对企业有效（《民法典》第170条）。
- 小企业可"法人=管理员=经办人"合一；大企业由法人授权采购负责人为管理员，后续经办人由管理员自助管理。
- **经办人变更由企业方自助操作并留痕，卖方后台实时同步**，从根本上解决"文字备案、换人失联"。

### 2.6.3 经办人变更管理（防换人失联与盗提）

- **责任转移**：服务协议 21.1 约定"未及时通知变更，原账号行为仍对企业有效，后果自负"。
- **自助增减**：经办人增/减/停用由企业管理员在系统操作，全程留痕。
- **定期复核**：周期性（如每季度）提醒企业管理员确认在职经办人名单；长期不活动账号自动休眠，重新激活需再认证。
- **盗提兜底**：大额/敏感提货叠加人脸核身（离职者刷不过）；新设备/新号登录、异常频次/车牌触发复核拦截。

### 2.6.4 事后兜底（万一确权缺失或企业仍抵赖）

| 兜底 | 法律依据 | 作用 |
|---|---|---|
| 表见代理 | 《民法典》第172条 | 采购员长期以企业名义、用企业账号提货，卖方有理由相信其有代理权 |
| 追认 | 《民法典》第171、503条 | 企业实际收货、对账、付款、受票等履行行为构成追认，不得再否认 |
| 实际履行证据 | —— | 对公付款、增值税发票往来、收货记录证明企业知情且受益 |

> 事后兜底强度弱于事前确权，仅作补充。**新客户/大额必须事前法人确权；老客户/小额可先款后货（对公打款）+ 表见代理兜底。**

### 2.6.5 大企业不配合时的分级应对（卖方话语权弱）

现实约束：钢贸常是卖方求大客户买货，无法强制大企业法人刷脸/盖电子章。应**降低对主动技术确权的依赖，改用大企业既有的正式动作确权**，并按信用分级差异化要求：

| 客户类型 | 确权方式 | 说明 |
|---|---|---|
| 大企业/优质客户 | **既有正式凭据 + 对公付款 + 留痕** | 盖章《授权书/指定提货人名单》、采购框架协议/PO；**对公付款本身即企业认可的强证据**；配合个人实名经办人 + 提货码 + 收货记录形成闭环 |
| 中小/新客户 | **法人意愿认证 / 先款后货** | 风险高，需强确权或款到发货 |

**关键做法**：
1. **以对公付款替代法人刷脸**：先款后货时，付款即企业意思表示，几乎不可抵赖。
2. **搭便车**：把服务协议条款嵌入大企业本就要签的年度采购框架协议（盖章），不单独增加客户动作。
3. **接受盖章凭据**：盖公章的指定提货人名单/PO 作为企业级授权，线下一次扫描存证。
4. **信用换流程**：大企业资产足、重声誉、走正规采购，跑路抵赖实际风险低，用"留痕 + 表见代理 + 实际履行"即足够，不必同等强度的事前确权。

> 原则：**强技术确权用于管不住的小客户；大企业用"商务正式凭据 + 对公付款 + 留痕兜底"，将合规融入其既有流程而非增加负担。**

### 2.6.6 "协议 + 付款凭证"作为企业确权依据：适用条件与边界

实务中可用「平台买卖/提货协议 + 对公付款凭证」作为企业级确权主依据，**替代法人刷脸/企业实名**，大幅简化。但须厘清其能力边界：

**三层概念区分（不可混淆）**：

| 层级 | 解决 | 手段 | 付款凭证+协议 |
|---|---|---|---|
| 企业意思表示 | 企业认不认这笔交易 | 对公付款 + 平台协议 | ✅ 强 |
| 个人实名 | 签署/操作者是不是真人 | 个人实名（身份证+本人核验） | ❌ 不能替代 |
| 提货执行 | 谁来提、提多少、是否本人 | 经办人实名 + 提货码 | ❌ 不能覆盖 |

**适用条件与约束**：
1. **仅"先款后货"成立**：赊销/月结/承兑等"先货后款"场景，提货时尚无付款凭证，不能以其作提货确权依据。
2. **付款账户须与买方同名**：对公账户付款方为买方企业本身；代付/个人户付款会显著削弱企业意思表示的证据力（见 2.6.7）。
3. **付款确认的是企业、非个人**：冒领、错放、数量争议等提货执行层问题，仍须经办人个人实名 + 提货码兜底。

**推荐最简组合（既简又不留坑）**：
- 企业层面：平台协议 + 对公付款凭证确权（去掉法人刷脸）；
- 个人层面：**保留经办人一次性个人实名（几毛钱/人，针对个人不增加企业负担）+ 提货码**，防冒领、锁定提货人，**不可省**。

### 2.6.7 平台作为唯一交易确认渠道

- 将平台设为**买卖双方唯一的交易、提货、结算确认渠道**，所有确认行为均在平台留痕存证，避免线下口头/即时通讯确认导致证据散乱。
- 应在《服务协议》中明确："双方一切交易、提货、结算确认以本平台记录为准；平台外的确认非经平台记录不发生效力。"
- 付款凭证作为确权依据时，建议在平台关联付款回单（付款人、收款人、金额、流水号），与协议、提货、结算串成同一证据链。

## 3. 三个核心法律时点的依据

### 3.1 经办人发起「提货指令暨收货确认」 —— 授权成立

> **确认合并**：因采用"出库即确认"，收货/交付确认不单设事后步骤，其认可语前置并入提货指令确认，经办人发起提货时一次完成（见 `04` 文档 F 段）。

- **机制**：买方实名经办人在线签署"授权某车牌/司机本次提取 XX 数量，并预先认可出库即确认与结算异议期规则"的提货指令。
- **法律支撑**：
  - 《在线提货与签收服务协议》预授权条款（见 `04` 文档）；
  - 《民法典》第170条 **职务代理**：执行法人或非法人组织工作任务的人员，就其职权范围内事项以单位名义实施的行为，对单位发生效力；
  - 《民法典》第172条 **表见代理**：相对人有理由相信行为人有代理权的，代理行为有效。

### 3.2 货物驶离仓库 —— 交付完成与风险转移

- **机制**："出库即确认"，货物经过磅、出库、驶离仓库时交付完成。
- **法律支撑**：
  - 《民法典》第604条：标的物毁损、灭失的风险，**交付前由出卖人承担，交付后由买受人承担**；
  - 买方自提场景下，交付地点在卖方处所，买方（或其授权司机）提走货物即完成交付；
  - 服务协议"自提交付与风险转移"条款明确约定该时点。

### 3.3 结算单送达后 T+N 无异议 —— 数量金额最终确认

- **机制**：结算单送达买方，约定期内无书面异议即视为认可数量与金额。
- **法律支撑**：
  - 《民法典》第140条第2款：**沉默只有在有法律规定、当事人约定或符合交易习惯时，才视为意思表示**——因此必须有明确约定；
  - 《民法典》第621条：**约定检验期间的，买受人在检验期间内未通知数量/质量不符的，视为符合约定**——这是"结算单 + 异议期"的直接法律依据。

#### 成立的三个前提（缺一不可）

1. **服务协议（及提货指令确认）明确约定**异议期与沉默后果；
2. **结算单送达可举证**（系统推送日志、已读回执、短信/邮件发送记录）；
3. **异议期合理**（建议 ≥ 2~3 个工作日，避免被认定过短不合理）。

## 4. 第三方驾驶员授权链的合规设计

### 4.1 风险

第三方司机与买方无劳动关系，其提货行为不必然约束买方，买方可能抗辩"非我员工、未授权"。

### 4.2 合规闭环

```
实名经办人 (服务协议预授权)
   └─ 在线签署提货指令，生成一次性提货码（绑定车牌/数量/时段）
        └─ 提货码 = 买方对本次司机提货的具体授权凭证
             └─ 仓库核验提货码 + 车牌 → 放行
                  └─ 买方不得否认（服务协议"驾驶员代提授权"条款）
```

- 实名分量由经办人承担，司机端可免实名；
- 提货码是"一次一授权"的具体化，证明买方对该次提货的明确授权；
- 服务协议"驾驶员代提授权"条款排除买方"非员工/未授权"抗辩。

> **车牌变更须重新确认**：提货码绑定的车牌属**授权范围**，授权指向某一具体车辆。车牌改动即授权对象改变，**必须由经办人重新确认（二次意愿认证）并存证后方可放行**；静默放行将导致授权越界、冒领风险及交付举证薄弱。流程见 `03` 文档 3.3.1。

### 4.3 授权委托书是否必备？——非必备

- **非大额单可不出具授权委托书，存证依然有效。** 授权链已由"服务协议预授权（企业级背书）+ 经办人个人实名电子签名 + 提货码 + 职务/表见代理 + 实际提货履行"构成完整闭环。
- **存证有效性**取决于"可靠电子签名 + 可信时间戳 + 防篡改存证"，与有无委托书无关，照样可出证。
- **前提**：开户的《在线提货与签收服务协议》必须有，且最好由法人意愿认证/电子章背书；这是替代合同后授权链的根基，**不可省**。
- 仅当单笔货值很高、风险偏好谨慎时，再对该客户补出具授权委托书加固（见 `04` 文档 I 段）。

## 5. 证据链合规要求

每次提货须自动归集并存证以下证据（详见 `05` 文档）：

1. 经办人实名提货指令（电子签名 + 时间戳）；
2. 提货码核验记录；
3. 车牌识别抓拍；
4. 过磅单/磅码单（毛重/皮重/净重 + 时间）；
5. 出库单；
6. 闸口/磅房视频或照片；
7. 出库时间戳 + 区块链/哈希存证；
8. 结算单送达记录与异议期记录。

存证要求：原始数据哈希上链或写入可信存证机构，确保事后**不可篡改、可验证、可出证**（司法鉴定/公证报告）。

## 6. 个人信息保护合规（《个人信息保护法》PIPL）

实名认证、人脸识别涉及敏感个人信息，须满足：

| 要求 | 落地 |
|---|---|
| 告知—同意 | 实名/人脸前弹出独立授权同意，明确收集目的、范围、保存期限 |
| 最小必要 | 仅收集核验所需的姓名、身份证号、手机号、人脸特征 |
| 单独同意 | 人脸等敏感信息须单独勾选同意 |
| 加密存储 | 身份证号、人脸数据加密；人脸特征建议不落地或脱敏存储 |
| 委托处理协议 | 与第三方实名/电子签服务商签订数据处理协议（DPA） |
| 出境合规 | 数据不出境；如用境外服务需评估（一般不涉及） |

## 7. 合规检查清单（上线前自查）

- [ ] 数字证书由持牌 CA 机构签发
- [ ] 接入可信时间戳服务
- [ ] 接入区块链/哈希存证，支持出具存证报告
- [ ] 《在线提货与签收服务协议》（开户一次签署）含：预授权、自提交付与风险转移、驾驶员代提授权、结算异议期四类条款，并由法人意愿认证/电子章背书
- [ ] 留货单含背书条款，引用服务协议
- [ ] 结算单送达具备可举证机制
- [ ] 异议期设置合理（≥ 2~3 个工作日）
- [ ] 实名/人脸前有合规告知同意，敏感信息单独同意
- [ ] 与服务商签订数据处理协议（DPA）
- [ ] 个人敏感信息加密存储、最小必要
